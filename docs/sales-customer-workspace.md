# 営業・顧客管理の機能境界

## 正本となるデータ

- 会社、連絡先、見込み企業、リード、商談、顧客はCRMの既存テーブルを参照する。画面ごとに顧客情報を複製しない。
- リスト・顧客区分はCRMレコードを条件で抽出する保存ビュー。宛先データ自体は保存しない。
- フォーム定義とフォーム回答は `diagnosis_forms` / `diagnosis_submissions`。診断記録とAIレポートは既存の `diagnoses` / `ai_reports`。
- 生成書類、契約、請求、顧問・構築支援はCRM IDに関連付ける。
- LINE / メール / 書類の送信依頼は `communication_outbox` に集約する。送信結果を手で「送信済み」に変更しない。

## 画面の役割

1. **顧客・営業**: 会社、連絡先、見込み企業、リード、商談、顧客の現在状態。
2. **フォーム・診断**: フォーム定義、受け取った回答、診断記録、診断レポート。
3. **リスト・顧客区分**: CRMを条件で絞る保存ビュー。配信対象の正本はこのビュー。
4. **顧客書類**: ひな形への差し込み、CRMレコードへの関連付け、確認待ち保存。
5. **LINE・メール配信**: シナリオ、個別送信、一斉送信、配信の承認と履歴。
6. **契約・請求・支援**: 契約成立後の契約状態、請求・入金、顧問や構築支援の実務。

## 受け付けから契約後まで

`フォーム / LINE / 手動受付 → 連絡先・リード → 診断・商談 → 書類生成 → 人の確認・承認 → outboxに送信依頼 → 契約・請求・支援の状態更新`

送信依頼は書類画面などから作成できるが、実際の送信処理、プロバイダー応答、再送制御は配信機能に集約する。請求・顧問・構築支援の状態は契約後業務側が持ち、期日案内だけを配信機能へ依頼する。

## この変更で有効になる範囲

- 営業ナビを機能グループに分けて折り返し表示する。
- フォーム定義と回答管理を診断画面内に追加する。公開フォームURL・匿名回答APIは未接続のため、公開状態にはしない。
- 条件付きCRM保存ビューを作成し、対象レコードのプレビューを行う。マーケティングシナリオは保存ビューIDを参照する。
- 契約・請求・顧問・構築支援を専用画面で管理する。旧ワークスペースJSONに保存されている契約・請求は移行SQLでリレーショナルテーブルへコピーし、旧IDを保持する。
- 顧客書類をCRMレコードに紐付けて確認待ち保存し、承認後に送信依頼を作成する。
- 配信同意の確認根拠と承認状態をoutboxに記録する。

## 外部連携の境界

LINE公式アカウントやメール送信サービスの資格情報・送信アダプターは、この画面変更だけでは追加されない。outboxの「送信待ち」は実配信完了を意味しない。サーバー側送信処理、Webhookによる返信・配信結果の取り込み、予約実行、公開フォーム受付は、資格情報と実行環境を設定した後に接続する。
