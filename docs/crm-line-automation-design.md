# CRM・LINE・業務自動化の統合設計

## 正本と状態遷移

- **会社マスタ**は会社情報の正本。各レコードはcompany_idで参照する。通常の新規登録入口は会社マスタではなく、AI調査候補の採用、CSV取込、見込み企業追加、診断/相談受付、LINE/メールから得た情報。会社マスタ画面は検索・重複確認・編集に使う。
- **連絡先**は個人の正本。会社が不明でも登録可能。1社に複数人を紐付けられる。
- **見込み企業**は営業対象として採用した会社とアプローチ状況。
- **リード**は診断・相談・問い合わせ・返信など具体的な関心を示した人/案件。LINE友だち追加だけではリード化しない。
- **商談**は提案・見積・受注の案件。
- **顧客**は契約後の提供関係。会社情報を複製しない。契約・請求・サポートは顧客に紐付く別レコード。
- **診断フォーム**はフォーム定義と公開状態、**診断回答**は回答者・回答・流入元・審査状態を保存する。確認後に連絡先/リード/社内診断へ紐付ける。
- **LINE友だち**は連絡先に紐付くチャネル情報。LINE user ID、友だち状態、追加/ブロック、最終接触、配信同意、タグを持つ。

標準経路は「調査/CSV/手動候補 → 会社照合 → 見込み企業 → 関心発生 → リード → 商談 → 契約 → 顧客・請求・サポート」。個人申込では会社IDは任意。

## 登録・更新元

| データ | 自動取込 | 手動入口 | 確認・重複対応 |
| --- | --- | --- | --- |
| 会社 | AI調査、CSV、フォーム、LINE/メール情報 | 電話/紹介/例外 | 名前+Webサイト/ドメイン候補を照合し、曖昧なら人が選択 |
| 連絡先 | フォーム、LINE webhook、返信取込 | 電話/紹介 | メール/電話/LINE IDで候補提示 |
| 見込み企業 | AI調査/CSVの候補から採用 | 会社を選び営業対象化 | 既存会社に紐付け、二重登録を抑止 |
| リード | 診断・相談・問い合わせ・返信 | 電話/紹介 | 既存連絡先を選択、会社なしも許容 |
| 商談 | 条件を満たしたリードから起票 | 例外的な直接起票 | リード/会社/連絡先を引継ぎ |
| 顧客・請求タスク | 契約成立・契約条件・期日 | 例外修正 | 契約の会社/連絡先と関連付け |

## LINE運用

LINE webhookで友だち追加/ブロック/メッセージイベントを受け、冪等キー付きで保存する。新規友だちは連絡先とLINE友だち台帳に登録し、タグを付けられる。友だち追加を営業リードとみなさず、診断・相談・問い合わせが発生した段階でリードへ変換する。

運用画面の機能単位は、友だち/タグ、1:1受信箱、対象抽出と一斉配信、シナリオ、Flex/画像メッセージ、リッチメニュー、配信/返信履歴。送信はLINE公式アカウントMessaging API接続後にのみ有効化し、同意・ブロック・重複送信・承認設定を適用する。公開診断はフォームURLをLINEテキスト/Flex/メールから案内する。

L Harnessの機能を参考にするが、MSTOSのSupabaseを顧客・タグ・診断データの正本として統合し、別DBを二重運用しない。OSSコードを直接移植する場合はMITライセンス表示と依存関係/セキュリティを確認する。

## 自動化とAIの境界

**通常プログラムで実行**：取込・検証・重複候補・点数計算・状態遷移・期日判定・リマインド候補・商品/契約データ差込・請求予定・タスク作成・冪等処理・実行履歴。

**必要時のみAIを呼ぶ**：企業調査/適合理由、診断の解釈・根拠付き提案、個社提案の構成、メール/LINE案内文、面談要約。会話履歴を無関係な処理に再送しない。

**人の承認を挟む**：初回/一斉配信、診断レポートの外部送付、提案金額・契約条件、請求額/送信、顧客向け重要連絡。本番送信は送信先・内容・対象件数をプレビューしてから行う。

## 実装段階と現在地

1. **データ基盤**：会社・連絡先・LINE友だち/タグ・公開診断フォーム/回答・外部イベント履歴をSupabaseへ追加。今回のmigrationが対象。
2. **入口**：見込み企業の採用/CSV取込、会社照合、フォーム公開受付、LINE webhook、メール返信取込。
3. **CRM連携**：受付から連絡先/リード作成、リードから商談、契約から顧客/請求予定/フォロータスクを冪等に生成。
4. **LINE/メール運用**：受信箱、タグ/セグメント、一斉/個別/シナリオ、Flex/画像、リッチメニュー、予約配信と履歴。
5. **AI支援**：各役割の草案/判断支援を既存モデル接続へ追加し、実行権限は通常プログラムと承認設定で制御。

現状のシナリオ画面は設定保存までで実送信しない。migrationを適用しただけで公開フォーム、LINE webhook、メール送信が稼働するわけではない。各入口のサーバー/APIと認証情報設定を別途実装してから有効化する。
