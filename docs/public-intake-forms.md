# 公開フォームからリード登録する

この機能は「フォーム作成 → 公開URL発行 → 診断・相談・面談の回答受付 → 連絡先とリードへの紐付け」までを扱います。診断結果の作成・送付、営業フォローメール、面談カレンダー連携は後続の実装です。

## 初回セットアップ

1. `supabase/migrations/20261016130000_public_intake_forms_to_leads.sql` と `supabase/migrations/20261016143000_intake_company_name.sql` の内容をSupabase SQL Editorでそれぞれ一度実行します。フォーム種別、送信再試行時の重複防止キー、申込者の会社名保存欄を追加します。
2. Expressサーバーの環境変数に `SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` を設定します。既存のLINE webhookで同じサーバー設定を済ませている場合は、その設定を使えます。
3. アプリとExpressサーバーをデプロイします。公開フォームURL `/f/{slug}` はアプリの画面を、`/api/public/forms/*` はExpress APIを同じオリジンから配信できる必要があります。静的ファイルだけのホスティングではAPIを受けられないため、APIへのリライトを設定してください。
4. 営業・顧客管理の「フォーム・診断」でフォームを作り、個人情報の取り扱い案内を入力して保存します。
5. 保存したフォームを一覧から選び、「公開する」を押します。表示されたURLをコピーしてLPやLINEに掲載します。

サービスロールキーはサーバー専用です。ブラウザー用の `VITE_*` 環境変数には設定しないでください。

## フォーム定義

受付種類は「診断申込」「相談申込」「面談申込」から選べます。設問はフォーム定義JSONの `questions` に設定し、`id`、`label`、`type`、任意の `required` を指定します。選択式の `select`、`radio` には `options` を指定します。説明文は `description` に設定できます。

種類を選び直すと、新しいフォームではその種類の設問例を読み込みます。既存フォームの設問は、切り替えただけでは置き換わりません。

## 回答後の登録

- 氏名・メールアドレスを取得し、電話番号と会社名・屋号は任意で受け付けます。
- メールアドレスで既存の連絡先を照合し、見つからなければ新規作成します。
- 入力された会社名・屋号が会社マスタと一致すれば紐付けます。一致しない名称は会社マスタに自動追加せず、申込回答とリードの記録に残します。
- その連絡先に紐づく最新のリードがあれば回答内容を追記します。なければ、診断申込・相談申込・面談申込の状態を持つリードを作成します。
- 会社がフォームから特定できない場合は、会社未設定のまま保存します。
- 回答レコードには連絡先、リード、回答、個人情報への同意日時、流入元を保存します。
- 送信の再試行では、同じリクエストIDを使って二重登録を防ぎます。

アプリに記録されるのはフォームの受付とCRMへの紐付けまでです。診断結果や案内の内容確認・送信、営業フォローの自動化はまだ行いません。
